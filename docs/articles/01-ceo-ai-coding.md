# CEO 不需要学会写代码，但必须学会指挥 AI 做产品

> 系列第 1 篇 · 《给 CEO 的 AI Coding 课：从一个经营想法，到一套可用的企业驾驶舱》
> 核心承诺：不需要成为程序员，也能借助 AI，把经营指标、企业数据和管理逻辑做成可运行的软件。

---

## 一、一个 CEO 都懂的业务问题

先讲个几乎每个老板都经历过的场景。

月底经营会，你问了一句："上个月利润为什么比预期低了？"

会议室安静两秒。财务说"数据还在核对"，销售说"可能是几个大项目回款慢"，运营说"投放费用涨了"。三天后，你微信收到一张 Excel：二十行数字，三个部门的口径还不一样，利润的定义跟去年都对不上。

你真正想要的，其实只是一句话：**哪里出了问题，谁负责，下一步做什么。**

但现实是：数据散在 Excel、ERP、CRM、财务系统里，每月靠人手拼；你看到的是"数据"，不是"问题"；想看一个指标的变化，要等别人排期做报表。

这背后不是"缺人"，是"缺一套把经营数据变成经营判断的系统"。

而这，正是 AI Coding 能给 CEO 的东西——不是替你写代码，而是帮你把脑子里那个模糊的经营想法，变成一套能跑起来、能看、能追问的系统。

## 二、本篇要完成什么

很多人一听"AI 写软件"，脑子里立刻冒出三个误区。今天先把它们拆掉：

**误区一：AI Coding 是让 CEO 替代程序员。**
错。专业工程师写的是系统、架构、并发、安全。CEO 用 AI 写的是自己业务的"驾驶舱"——一个只服务自己公司、能看指标、能发现问题的小系统。这是分工，不是替代。你定义要什么，AI 和工程师一起把它做扎实。

**误区二：输入一句话，就能生成一个商业系统。**
"帮我做个经营驾驶舱"——这句话让 90% 的 AI Coding 项目死在第一步。AI 不会读心。它能做的，是把你讲清楚的需求，翻译成可运行的代码。需求不清楚，出来的就是个空壳 Demo。

**误区三：CEO 最重要的是学编程语法。**
最不重要的就是这个。你不需要知道 `useEffect` 是什么，也不需要背 SQL。你真正要练的能力只有两个：**把问题定义清楚，把结果验收明白。**

所以本篇结束，你要拿到四样东西：

1. 一句话说清"驾驶舱解决什么问题"；
2. 一张第一版系统框架图；
3. 四个核心经营模块；
4. 一个项目目录 + 一份 AI 协作规则。

最终产出是一张「CEO 经营驾驶舱需求卡」（文末附模板，可直接复制填写）。

## 三、给 AI 的关键提示词

这是本篇最重要的"武器"。你不需要改代码，但需要学会给 AI 下指令。

第一次和 AI 搭项目，建议直接粘贴这一整段：

```
我要用 AI Coding 做一个"CEO 经营驾驶舱"教学项目，技术栈用 Next.js + Supabase。
请帮我：
1. 创建一个项目目录 lite/，用 Next.js（App Router）+ TypeScript + Tailwind CSS；
2. 在 lib/metrics.ts 里定义"统一经营指标"结构：每条指标含 指标编码、指标名称、所属模块、周期、当前值、目标值、同比、环比、单位、数据来源、负责人；
3. 先放一组脱敏模拟数据，让首页能在不接数据库的情况下跑起来；
4. 首页展示四大模块：经营结果、客户增长、项目与交付、组织效率；
5. 写一个 AGENTS.md，规定"先模型后页面、模拟数据先行、统一指标契约、每篇对应一个分支"的协作规则。
不要写真实业务数据，不要引入真实账号。
```

你会发现：当需求被拆成"结构 + 数据 + 页面 + 规则"四块，AI 的输出立刻从"天马行空"变成"可验收"。

（这个提示词对应的目录和规则，已经在课程配套仓库 `lite/` 里真实跑通了——你看到的不是概念，是已经能打开的页面。）

## 四、实际搭建过程（CEO 视角）

我用上面那段提示词，让 AI 搭出了第一版骨架。作为 CEO，你只需要看懂这四步，不需要亲手敲：

**第 1 步：定模型，不急着装页面。**
AI 先在 `lib/metrics.ts` 里把"一条指标长什么样"写死——编码、名称、口径、当前值、目标值、同比、环比、来源、负责人。这一步最关键：以后所有数据，不管来自 Excel 还是 ERP，都先变成这个统一格式。这是整套系统的"地基"。

**第 2 步：塞一组模拟数据。**
没接真实系统前，先用脱敏假数据把页面填满（比如月度收入 128 万、目标 150 万、同比 +12%）。目的是让你今天就看到"驾驶舱长什么样"，而不是空等系统打通。

**第 3 步：首页跑起来。**
打开就是四个模块入口 + 核心指标卡片。有红黄绿——收入达标是绿，利润不达标是红。注意，这里红色代表"没达标"，不是"报错"，这是经营视角，不是技术视角。

**第 4 步：立规矩。**
`AGENTS.md` 写清楚：每篇课程对应一个 Git 分支；任何新指标必须先进统一模型再渲染；模拟数据先行。规矩定了，后面八周才不会乱。

你看，全程你没写一行代码，但你定义了"指标必须统一""先看到东西再接数据""每篇留痕"。**这些决定，比写代码值钱。**
